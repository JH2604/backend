# 校园失物招领系统 · 后端接口文档

## 一、通用约定

### 请求
- 服务地址：`http://<服务器IP>:8000`
- 请求体格式：`application/json`
- **需要登录的接口**，请求头要带：
  ```
  Authorization: Bearer <token>
  ```
### 关于 token

- **登录成功后**，token 在响应的 `data.token` 里
- 之后每个需要登录的接口，请求头都要带：
  Authorization: Bearer <token>        ← 注意 Bearer 后面有个空格
- **有效期 24 小时**，过期后要重新登录
- **token 里只包含 `user_id` 和 `role`**，没有别的用户信息
  （所以前端不要指望从 token 里读用户名，需要就调 /api/me）
- 想验证 token 还有没有效 → 调 `GET /api/me`，能返回就是有效

### 关于错误码

- **任何接口都可能返回 `50000`（服务器内部错误）** ——
  前端应该统一处理这一种，提示"服务暂时不可用，请稍后重试"，而不是逐个接口写。

### 响应格式

**所有接口**统一返回这三个字段：

```json
{
  "code": 0,
  "msg": "成功",
  "data": { }
}
```

| 字段 | 说明 |
|---|---|
| `code` | **业务码**。`0` 表示成功，非 0 表示出错 |
| `msg` | 给人看的消息 |
| `data` | 成功时是数据；出错时可能是具体原因 |

### 错误码表

| code | msg | 什么情况 |
|---|---|---|
| 0 | 成功 | |
| 20001 | 用户名已存在 | 注册时撞名 |
| 20002 | 用户名或密码错误 | 登录失败（不区分是用户名错还是密码错）|
| 40001 | 参数错误 | 请求参数格式/范围不对 |
| 40002 | 资源不存在 | 按 ID 查东西没查到 |
| 40003 | 未登录或登录已过期 | 没带 token / token 无效 / token 过期 |
| 40004 | 没有权限 | 登录了，但角色不够 |
| 50000 | 服务器内部错误 | 后端自己出问题 |

## 二、用户模块

### 1. 注册

- **方法路径**：`POST /api/register`
- **是否需要登录**：否
- **请求体**：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| username | string | 是 | 3~20 个字符 |
| password | string | 是 | 6~32 个字符 |

- **成功返回**：
```json
{ "code": 0, "msg": "成功", "data":"zhangsan"}
```
- **失败情况**：
  - 参数不合法 → `40001`
  - 用户名已存在 → `20001`

---


### 2. 登录

- **方法路径**：`POST /api/login`
- **是否需要登录**：否


- **成功返回**：
```json
{ "code": 0, "msg": "成功", "data":{"token":"eyJhbGci..."}}
```
- **失败情况**：
  - 参数不合法 → `40001`
  - 用户名或密码错误 → `20002`

---

### 3. 获取当前用户
- **方法路径**:`GET /api/me`
- **是否需要登录**：是

- **成功返回**:
```json
{"code":0,"msg":"成功","data":{"user_id":14}}


```
- **失败情况**：

  - 不带 token / token 过期/token是假的/token被改过 → `40003`

---

## 三、失物招领模块

### 1. 发布失物招领

- **方法路径**：`POST /api/v1/lost-items`
- **是否需要登录**：否
- **请求体**：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| title | string | 是 | 标题，不能为空（纯空格也不行） |
| location | string | 否 | 地点 |
| desc | string | 否 | 详细描述 |

- **成功返回**：
```json
{"code":0,"msg":"成功","data":{"id":3,"title":"校园卡","location":"图书馆","desc":"蓝色卡套"}}
```
- **失败情况**：
  - 缺少 title → `40001`
  - title 全是空格 → `40001`

---

### 2. 获取失物招领列表

- **方法路径**：`GET /api/v1/lost-items`
- **是否需要登录**：否
- **查询参数**：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| location | string | 否 | 按地点模糊筛选，不传则返回全部 |

- **请求示例**：`GET /api/v1/lost-items?location=图书馆`
- **成功返回**：
```json
{"code":0,"msg":"成功","data":[{"id":3,"title":"校园卡","location":"图书馆","desc":"蓝色卡套"}]}
```
- **失败情况**：
  - 查询失败 → `50000`
  - 没查到数据 → `code` 仍是 `0`，`data` 为 `[]`

---

### 3. 获取失物招领详情

- **方法路径**：`GET /api/v1/lost-items/:id`
- **是否需要登录**：否
- **路径参数**：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| id | int | 是 | 记录 ID，正整数 |

- **请求示例**：`GET /api/v1/lost-items/3`
- **成功返回**：
```json
{"code":0,"msg":"成功","data":{"id":3,"title":"校园卡","location":"图书馆","desc":"蓝色卡套"}}
```
- **失败情况**：
  - id 不是数字 → `40001`
  - 记录不存在 → `40002`
